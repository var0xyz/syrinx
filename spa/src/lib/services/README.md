# Signature Verification Service

This service provides client-side verification of HTTP response signatures generated by the Syrinx server's `responseSigner` middleware. The signatures cover the complete response (headers + body).

## Features

- **Automatic signature verification** for API responses
- **TypeScript support** with full type definitions
- **OpenPGP.js integration** for cryptographic verification
- **Canonical header string building** matching server implementation
- **SvelteKit integration** examples

## Usage

### Basic Usage

```typescript
import { secureApiRequest } from '$lib/services/signature-verifier';

// Make a secure API request
const response = await secureApiRequest('/api/users/me', {
  method: 'GET'
}, 'your-server-public-key');

if (response.signatureValid) {
  const data = await response.json();
  console.log('Verified data:', data);
}
```

### Automatic Server Key Fetching

```typescript
import { secureApiRequestWithAutoKey } from '$lib/services/signature-verifier';

// Automatically fetches server public key
const response = await secureApiRequestWithAutoKey('/api/users/me');
```

### Manual Verification

```typescript
import { verifyResponseSignature, buildCanonicalHeaderString } from '$lib/services/signature-verifier';

const response = await fetch('/api/users/me');
const isValid = await verifyResponseSignature(response, serverPublicKey);
```

## API Reference

### Functions

#### `buildCanonicalHeaderString(headers)`
Builds a canonical string representation of response headers.

**Parameters:**
- `headers: Headers | Record<string, string | string[]>` - Response headers

**Returns:** `string` - Canonical header string

#### `addArmorDelimiters(signature)`
Adds PGP armor delimiters to a stripped signature. Used internally by the verification process.

**Parameters:**
- `signature: string` - Signature without armor delimiters

**Returns:** `string` - Signature with armor delimiters

#### `verifyResponseSignature(response, serverPublicKey)`
Verifies the Signature header for a response.

**Parameters:**
- `response: Response` - Fetch API Response object
- `serverPublicKey: string` - Armored PGP public key

**Returns:** `Promise<boolean>` - True if signature is valid

#### `secureApiRequest(url, options, serverPublicKey?)`
Fetch wrapper that automatically verifies response signatures.

**Parameters:**
- `url: string` - URL to fetch
- `options: SecureApiRequestOptions` - Fetch options
- `serverPublicKey?: string` - Server's public key for verification

**Returns:** `Promise<Response>` - Response with `signatureValid` property

#### `secureApiRequestWithAutoKey(url, options)`
Enhanced secure API request with automatic server key fetching.

**Parameters:**
- `url: string` - URL to fetch
- `options: FetchOptions` - Fetch options

**Returns:** `Promise<Response>` - Response with `signatureValid` property

### Types

#### `SecureApiRequestOptions`
Extends `RequestInit` with optional `serverPublicKey` property.

#### `FetchOptions`
Standard `RequestInit` interface.

## Requirements

- **OpenPGP.js**: Bundled from the `openpgp` npm package (`openpgp/lightweight`)
- **Server public key**: Required for verification (can be fetched automatically)
- **Newline unescaping**: Signatures are automatically processed to unescape newlines for verification

## Setup

1. **Import the service** in your SvelteKit components:
   ```typescript
   import { secureApiRequest } from '$lib/services/signature-verifier';
   ```

2. **Use in your load functions** or components:
   ```typescript
   // In +page.ts
   export const load = async () => {
     const response = await secureApiRequestWithAutoKey('/api/users/me');
     return {
       user: response.signatureValid ? await response.json() : null
     };
   };
   ```

## Security Notes

- Always verify signatures before trusting response data
- Store server public keys securely
- Consider caching verified responses
- Log signature verification failures for monitoring

## Troubleshooting

### "OpenPGP.js not loaded"
- Ensure OpenPGP.js is loaded before using the service
- Check browser console for loading errors

### "No Signature header found"
- Verify the server is running the responseSigner middleware
- Check that the request is going to the correct API endpoint

### "Signature verification failed"
- Verify the server public key is correct
- Check that headers haven't been modified by proxies
- Ensure canonical header format matches server implementation
