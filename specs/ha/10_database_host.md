# HA 10 — Database host

## Status

Proposed.

## Depends on

[01](01_replica_mode.md)

## Context

`setup.sh` installs Postgres next to the app, listening on loopback, with
SCRAM auth and one role/database named after the app. In HA, Postgres moves
to its own Pi and every app host connects over the LAN.

## Postgres on the DB host

- `listen_addresses = '<LAN IP>'`, not `*`.
- `pg_hba.conf`: one `host <db> <role> <app-ip>/32 scram-sha-256` line per
  app host, generated from the topology. Nothing else from the LAN.
- TLS between app and DB is optional on a trusted LAN; `DB_SSLMODE`
  already exists if the operator wants it (`require` + a self-signed cert
  generated by setup).
- Tuning for a Pi with the whole machine to itself (example: 8 GB):
  `shared_buffers = 2GB`, `effective_cache_size = 6GB`,
  `work_mem = 16MB`, `max_connections = 100`. Setup writes these into a
  `conf.d/syrinx.conf` drop-in, sized from `MemTotal`.
- `synchronous_commit` stays `on`; the app already turns it off per
  transaction where only unlogged tables are written.
- Nightly `pg_dump -Fc` to a local directory with 7-day rotation, and a
  documented one-liner to pull the latest dump to the operator's machine.
  Unlogged tables are skipped by `pg_dump --no-unlogged-table-data`, which
  is what we want.

## Connection budget

The app sets no pool limits today. Add, in both modes:

| Variable | Default | Meaning |
|---|---|---|
| `DB_MAX_OPEN_CONNS` | 10 | `SetMaxOpenConns` |
| `DB_MAX_IDLE_CONNS` | 5 | `SetMaxIdleConns` |

Plus one connection per replica for the boot lock while booting. Setup refuses a topology where
`replicas × (max_open + 2) + jobs + 10 (admin/psql headroom)` exceeds
`max_connections`.

## Commands that touch the DB

`psql` and `wipe-db` run on the DB host. `wipe-db` in HA stops the gateway
and every app host, drops and recreates the database, starts the app hosts
one at a time, then the gateway, whose start performs the realtime reset
([07](07_server_wide_reset.md)).

## Tests

- Setup on a fresh DB Pi: app hosts in `pg_hba` can connect; another LAN
  host can't.
- Pool cap respected under load (no `too many clients` with 3 replicas
  under the load-test driver).
